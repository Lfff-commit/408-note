# 计算机组成原理：Cache 替换算法

> **导语**
> 本节课我们将探讨 Cache 的第二个核心机制：**Cache 替换算法**。
> 由于 Cache 容量远小于主存，当 Cache 被装满而 CPU 又需要调入新的主存块时，必须决定将 Cache 中的哪一个旧块“踢出去”。我们将学习四种常见的替换算法，并重点剖析在考试中最常考的 **LRU 算法**。

---

## 一、 为什么需要替换算法？ (触发前提)

在上一节学习的三种映射方式中，替换算法的适用情况是不同的：

1.  **全相联映射**：主存块可以放入 Cache 的任何位置。只有当整个 Cache **全部被装满**后，才需要使用替换算法。
2.  **直接映射**：主存块只能放入 Cache 的唯一固定位置。如果该位置已被占用，**毫无选择，只能直接覆盖替换**。因此，直接映射**不需要**复杂的替换算法。
3.  **组相联映射**：主存块只能放入特定的一个分组中的任意位置。当且仅当**该分组被装满**时，才需要在该分组内部使用替换算法。

> **结论**：替换算法主要用于**全相联映射**和**组相联映射**中。本节课为了简化演示，均以“全相联映射”为例进行讲解。

---

## 二、 四种 Cache 替换算法详解

### 1. 随机算法 (RAND - Random)

- **规则**：当 Cache 满了需要替换时，**随机**挑选一个 Cache 块淘汰掉。
- **优缺点**：
  - **优点**：实现极其简单。
  - **缺点**：完全没有考虑程序的局部性原理，可能刚把一个接下来还要用的重要数据给随机踢掉了，导致 Cache **命中率极低且不稳定**。实际应用效果差。

### 2. 先进先出算法 (FIFO - First In First Out)

- **规则**：优先淘汰**最先（最早）被调入** Cache 的块。
- **硬件实现思路**：像一个队列一样，按 `0 -> 1 -> 2 -> 3 -> 0 -> ...` 的顺序轮流替换即可。
- **优缺点**：
  - **优点**：规则简单，硬件实现容易。
  - **缺点**：同样**没有遵循局部性原理**。最先被调入 Cache 的块（比如 C 语言中的 `printf` 函数代码）可能在程序运行的整个生命周期中被频繁调用。把它们踢出去是不科学的。
  - **致命缺陷 (抖动现象)**：可能会出现刚被换出的块立刻又被访问，导致频繁换入换出的现象（即**抖动 / Thrashing**）。

---

### 3. 近期最少使用算法 (LRU - Least Recently Used) 【核心必考】

- **规则**：优先淘汰**最久没有被访问过**的主存块。
- **设计思想**：充分利用了**时间局部性原理**。既然你最近经常被用到，那说明你未来很可能还会被用到（留住你）；如果你很久都没被访问过了，说明你大概率已经失去利用价值了（踢掉你）。实际命中率在四种算法中是最高的！

#### A. 笔算做题神技 (逆向观察法)

当面临替换选择时，不要去推演计数器，直接：
**从当前将要访问的主存块位置开始，在访问序列中向左（往前）看，最后一个看到的主存块，就是要被替换掉的块！**
_(因为它就是最久没有被访问过的)_

#### B. 硬件底层实现 (计数器机制剖析)

为了用硬件实现 LRU，需要给每个 Cache 行增加一个**计数器**。假设 Cache 有 $2^n$ 行，计数器只需 $n$ 个比特位即可。以 4 个 Cache 行为例（计数器只需 2 bit，最大值为 3）：

**计数器变化铁律：**

1.  **新调入行**：新块被装入某个 Cache 行时，该行的计数器清 `0`。此时**其余非空闲行**的计数器全部 `+1`。
2.  **命中行**：当命中某个 Cache 行时，该行的计数器清 `0`。此时，**原计数值比它小**的那些计数器全部 `+1`，原计数值比它大的计数器保持**不变**。
3.  **替换规则**：需要替换时，选择计数器值**最大**（对于 4 行 Cache 就是为 `3`）的那个行淘汰。

> **深度思考：为什么要分“比它小”和“比它大”？**
> 对于 4 行 Cache，计数器的有效值只能是 `0, 1, 2, 3`。当淘汰时，我们只找值为 `3` 的。
> 如果命中了一个计数器为 `2` 的行，它清零后，原本为 `0` 和 `1` 的行加一变成 `1` 和 `2`，原本为 `3` 的行如果不加一，它仍然是全场最大，下一轮优先淘汰它。如果盲目让 `3` 也加一变成 `4`，不仅会溢出我们预设的 2 bit 容量，而且没有任何实际排序意义。

---

### 4. 最不经常使用算法 (LFU - Least Frequently Used)

- **规则**：优先淘汰**累计被访问次数最少**的主存块。
- **硬件实现思路**：为每个 Cache 行设置一个计数器。新调入时清 `0`，之后**每被访问一次，计数器就 `+1`**。替换时挑选计数值最小的。如有多个最小，则配合 FIFO 或行号顺序打破僵局。
- **优缺点**：
  - **优点**：看起来很科学，统计了全局的访问热度。
  - **缺点 (严重背离局部性)**：它统计的是“全局历史”，而程序运行关注的是“当前局部”。例如：你刚用微信打了 1 个小时视频，视频相关模块的计数值被加到了极大。之后你挂断视频开始打字，此时就算视频模块成了废数据，由于它的历史计数值太庞大，它在很长一段时间内都不会被淘汰，死死霸占着 Cache 空间，导致新加入的打字模块数据极易被挤出。**实际运行效果很差。**

---

## 三、 本节高频考点速记对比

| 算法简称 | 全称         | 替换规则                 |        局部性原理        | 硬件成本 / 实际效果                   |
| :------: | :----------- | :----------------------- | :----------------------: | :------------------------------------ |
| **RAND** | 随机算法     | 随机选一个踢掉           |        ❌ 未遵循         | 成本极低 / 效果极差                   |
| **FIFO** | 先进先出     | 踢掉最先放进来的         |        ❌ 未遵循         | 成本低 / 效果差，易抖动               |
| **LRU**  | 近期最少使用 | **踢掉最久没被访问过的** |  **✅ 完美遵循** (时间)  | **需设置计数器 / 命中率极高 (常考)**  |
| **LFU**  | 最不经常使用 | 踢掉历史访问总次数最少的 | ❌ 未遵循 (过度关注历史) | 计数器位数长 / 易造成旧热点霸占 Cache |

> **复习建议**：
>
> 1. 牢记直接映射**没有也不需要**替换算法。
> 2. 考试大题中，90% 考察的是 **LRU 算法**，熟练掌握“从后往前看，最后一个就是被替换者”的手算秒杀技巧。
