## 一、 中断处理流程的时间轴分析

引入中断机制后，CPU 无须再像程序查询方式那样不断轮询（“忙等”）I/O 设备的状态，而是可以与外设**并行工作**。

我们来看看一次完整的中断处理在时间轴上是如何展开的：

```mermaid
gantt
    title CPU 与 I/O 设备并行工作时序图
    dateFormat  s
    axisFormat %S

    section CPU 执行序列
    执行主程序 (地址k)      :active, m1, 0, 4s
    检测到中断请求并响应 (隐指令) :crit, m2, 4s, 1s
    保护现场并处理数据 (服务程序前段) :m3, 5s, 3s
    向外设发出新启动命令     :milestone, m4, 8s, 0s
    恢复现场并返回 (服务程序后段) :m5, 8s, 2s
    继续执行主程序 (地址k+1)    :active, m6, 10s, 4s

    section 外设 I/O 执行序列
    外设准备第 1 个数据 (CPU此时在跑主程序) :done, io1, 0, 4s
    发送中断请求并等待CPU响应   :crit, io2, 4s, 4s
    外设准备第 2 个数据 (被CPU启动后)  :done, io3, 8s, 4s
```

### 1. 主程序与中断的交接

- **指令结束阶段检测**：CPU 在当前指令（地址为 $k$）的指令周期末尾，检测到外部设备发来的中断请求信号。
- **硬件介入（中断隐指令）**：CPU 暂停主程序，由硬件自动执行“中断隐指令”。完成三个不可打断的动作：
  1.  **关中断**（防止被新中断打断）。
  2.  **保存断点**（将下一条指令地址 $k+1$ 压栈）。
  3.  **引出中断服务程序**（生成入口地址，修改 PC）。

### 2. 中断服务程序的执行

进入中断服务程序后，软件开始接管：

- **保护现场**：保存主程序的运行环境（各种通用寄存器的值）和中断屏蔽字。
- **实质性处理**：从 I/O 接口的数据缓冲寄存器中取走刚刚准备好的数据（对于输入设备），或写入新的数据（对于输出设备）。
- **重新启动外设**：CPU 向 I/O 接口发出下一条启动命令。此时，**外设就可以立刻开始准备下一个数据了**！
- **恢复现场与中断返回**：CPU 恢复寄存器状态，执行中断返回指令，回到主程序 $k+1$ 处继续执行。

> **核心结论**：在中断处理的过程中，一旦 CPU 向外设发出新的启动命令，外设即可开始下一次的耗时操作，而 CPU 则可以从容地完成中断收尾工作并继续执行主程序，从而实现了**真正的并行**。

_(注：某些 I/O 操作如 `scanf` 确实会阻塞进程导致 CPU 等待，但像 `printf` 或底层的异步数据读写，CPU 完全可以继续向后推进，无需死等。)_

## 二、 经典真题实战演练

**【真题背景信息提取】**

- **CPU 性能**：已知 CPU 主频，平均每条指令执行周期数 (CPI) = $4$。
- **外设 D 参数**：传送一个字符，从接收启动命令到数据输入 I/O 端口（外设准备时间）需要 $0.5\text{ms}$。
- **中断处理参数**：
  - **中断响应阶段（中断隐指令）**：耗时 $10$ 个时钟周期。
  - **中断服务程序**：共 $20$ 条指令。其中，第 $15$ 条指令向外设发出“启动下一次工作”的命令，最后 $5$ 条指令用于后续处理（恢复现场等）。

### 问题 1：从外设启动到传送完 1 个字符，总共需要多少个时钟周期？读 1000 个字符呢？

**【解析】**
传送 1 个完整字符的时间线构成如下：

1.  **外设准备时间**：外设 D 收到启动命令后，耗时 $0.5\text{ms}$ 准备好一个字符。（注：由于题目给了主频，此处假设 $0.5\text{ms}$ 换算为时钟周期为 $25000$ 个周期）。
2.  **中断隐指令时间**：外设准备好后发中断，CPU 响应耗费 $10$ 个时钟周期。
3.  **中断服务程序（至取出字符并重新启动）**：取字符和发启动命令在第 $15$ 条指令完成。耗时为 $15 \times 	ext{CPI} = 15 \times 4 = 60$ 个时钟周期。

**单个字符耗时** = $25000 	ext{ (外设)} + 10 	ext{ (隐指令)} + 15 	imes 4 	ext{ (取数据)} = \mathbf{25070}$ 个时钟周期。
读 1000 个字符 = $25070 	imes 1000$ 个时钟周期。

> **防杠指南（关于末尾 5 条指令）**：
> 细心的同学会问，最后 5 条恢复现场的指令为什么没算进去？
> _理解 A_：在第 15 条指令执行完毕时，当前字符已经被取走，下一次的 I/O 也已经启动，可以说“本次字符传输已经实质性完成”。最后 5 条指令是 CPU 的善后工作，与字符传输时间的界定无关。（**推荐解法**）
> _理解 B_：认为必须等整个中断程序执行完毕，才算完成。此时加上 $5 	imes 4 = 20$ 个周期也算合理。
> _考试策略_：只要列出清晰的计算式，无论哪种理解通常都会给分，但推荐按“理解 A”作答。

### 问题 2：CPU 用于完成这一任务（处理 1000 个中断）实际耗费了多少时间周期？占总工作时间的比例？

**【解析】**
本题问的是 **CPU 真正被占用去干活** 的时间（外设在准备那 $0.5\text{ms}$ 数据时，CPU 是在跑别的主程序的，这部分不算在处理中断的时间内）。

处理**一次中断**的 CPU 纯消耗时间 = `中断隐指令时间` + `完整的中断服务程序时间`

- 隐指令时间 = $10$ 个周期
- 服务程序时间 = $20 	ext{ 条指令} 	imes 4 	ext{ (CPI)} = 80$ 个周期
- 单次 CPU 开销 = $10 + 80 = 90$ 个周期。

**处理 1000 次中断的 CPU 总开销** = $90 	imes 1000 = \mathbf{90000}$ 个时钟周期。
求比例时，将此开销除以总工作时间（问题 1 的结果加上最后一次的善后时间等）即可。

### 问题 3：中断响应阶段，CPU 做了哪些操作？

**【解析】**
这是一个纯理论送分题，考察对“中断隐指令”的记忆：

1.  **关中断**。
2.  **保存断点**（保存程序计数器 PC）。
3.  **引出中断服务程序**（找到并加载中断程序的入口地址）。

## 三、 本节小结

1.  **程序查询 vs 程序中断**：中断的核心价值在于将 CPU 从盲目的轮询中解放出来，实现了 CPU 与 I/O 设备的**宏观并行**。
2.  **时间轴拆解**：必须熟练掌握外设准备数据、隐指令响应、服务程序取数据并二次启动外设的**时间先后顺序**。
3.  **向量与向量地址**（补充提醒）：做题时注意区分，**中断向量**是服务程序的入口地址，而**向量地址**是存放这个中断向量在内存中的地址，两者类似于指针与双重指针的关系。
