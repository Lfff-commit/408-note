## 一、 中断的基本概念与作用

### 1. 为什么需要中断？

正常情况下，CPU 通过程序计数器 (PC) 顺序执行主存中的指令。即使遇到跳转指令 (Jump) 或函数调用 (Call)，执行流也依然局限在当前进程内部。这意味着，**如果不加干预，一个进程一旦上 CPU 运行，就会一直霸占 CPU**。
但在实际使用中，我们需要 CPU 能够响应键盘敲击、鼠标点击等**外部设备 (I/O 设备)** 发出的信号。为了解决这个矛盾，引入了**中断系统**。

### 2. 中断的核心机制

- **例行检查**：CPU 在执行完每一条指令后，在**指令周期的末尾**都会例行检查是否有**中断请求信号**需要处理。
- **打断与恢复**：如果检测到中断请求，CPU 会暂时改变当前的指令执行流，转而去执行一段专门的**中断服务程序**来响应这个请求。处理完毕后，再回到刚才被打断的位置继续执行原来的程序。
- **中断源**：能够产生中断请求信号的部件（如键盘、鼠标、打印机或时钟部件）被称为中断源。

## 二、 中断响应的条件与分类

并不是所有的中断请求 CPU 都会立刻理睬。CPU 响应中断需要满足一定的条件。

### 1. 关中断与开中断 (PSW 寄存器)

CPU 当前是否愿意响应中断，记录在**程序状态字寄存器 (PSW)** 的 `IF` (Interrupt Flag) 标志位中。

- **`IF = 1` (开中断)**：CPU 可以接收并响应中断请求信号。
- **`IF = 0` (关中断)**：CPU 暂时不理睬中断请求，继续执行当前程序直到再次开中断。
- **应用场景 (原子操作)**：如果希望某几条指令的执行过程绝对“一气呵成”不被任何外部信号打断（如数据库事务或操作系统的 PV 操作），就可以在这些指令前后加上“关中断”和“开中断”指令。

### 2. 中断的分类 (可屏蔽 vs 非屏蔽)

- **非屏蔽中断 (NMI)**：极其紧急的硬件故障（如突然掉电、强制关机等）。**即使 CPU 处于关中断状态 (`IF=0`)，也必须无条件立刻响应**。
- **可屏蔽中断**：普通的 I/O 设备请求。当 CPU 关中断时，这些请求会被暂时屏蔽。本章我们探讨的绝大多数 I/O 中断都属于这一类。

## 三、 中断判优：多请求同时到来的优先级排队

当多个中断源同时发来请求时，CPU 必须决定先处理哪一个。这由**中断判优**逻辑决定，通常通过**硬件排队器**实现以保证极高的速度。

### 1. 硬件排队器原理

通过触发器组成的**中断请求标记寄存器**记录所有发来请求的设备。然后通过类似非门和与非门组成的逻辑电路，确保即使有多个输入为 `1`，最终只有**优先级最高的那一根输出线为 `1`**，其余全部强行置 `0`。

### 2. 优先级设计原则 (常考选择题)

1.  **硬件故障中断** > 软件中断。
2.  **非屏蔽中断** > 可屏蔽中断。
3.  **DMA 请求** > I/O 设备传送的中断请求。
4.  **高速设备** > 低速设备（高速设备耽误不起，低速设备等一等没关系）。
5.  **输入设备** > 输出设备（输入不及时会被用户的下一次操作覆盖掉数据，而输出设备可以慢慢取数据）。
6.  **实时设备** > 普通设备。

## 四、 中断处理的完整工作流程 (★ 核心重难点)

确定了要响应哪个中断后，CPU 需要找到对应的中断服务程序并执行。整个流程分为两大阶段：**中断隐指令 (硬件自动完成)** 和 **中断服务程序 (软件执行)**。

### 阶段一：中断隐指令 (硬件自动寻找入口并保存断点)

“中断隐指令”不是一条具体的汇编指令，而是 CPU 检测到中断后**由底层硬件自动完成的一系列动作**的统称。它包含三个核心任务：

1.  **关中断**：将 `IF` 置 0，防止在保存现场的紧要关头被新中断打断。
2.  **保存断点**：将原来程序本该执行的下一条指令地址 (即 `PC` 的值，指向 $K+1$) 压入系统内核堆栈中保存。
3.  **引出中断服务程序 (寻找入口地址)**：
    - 硬件排队器输出高电平信号后，输入到**中断向量地址形成部件**。
    - 该部件输出一个**向量地址 (中断类型号)**。
    - CPU 根据这个向量地址去内存中查找**中断向量 (Interrupt Vector)**。
    - **中断向量的本质是一条无条件转移指令 (Jump)**，它里面存放的才是真正的中断服务程序的入口地址。将此地址赋给 `PC`。

> 🚨 **易混淆概念区分：中断向量 vs 向量地址**
>
> - **中断向量**：指向服务程序入口的“函数指针”。
> - **向量地址**：存放这个中断向量（指针）在内存中位置的“指针的指针”。
> - _为什么搞这么复杂（两级指针）？_ 因为中断服务程序更新或变长时入口地址会变，我们只需要修改内存中的“中断向量”即可，而不用去修改固化在硅片上的硬件电路。

### 阶段二：中断服务程序 (软件接管执行)

此时 PC 已经指向了中断服务程序的第一条指令，接下来的操作由程序员编写的指令来完成。

1.  **保护现场**：将原程序运行时的各个通用寄存器、累加器 `ACC` 等中间结果压入堆栈保存，以免被当前中断程序破坏。
2.  **中断服务主体**：实质性的处理逻辑（如取出键盘敲击的字符，或往打印机写入字符）。
3.  **恢复现场**：从堆栈中弹出之前保存的各个寄存器的值，恢复原程序的执行环境。
4.  **开中断并返回**：
    - 执行**开中断**指令 (`IF` 重新置 1)。
    - 执行中断返回指令，从堆栈顶弹出当初保存的断点 `PC` 值 ($K+1$)。
    - 程序执行流完美回到原程序断点处，仿佛什么都没发生过。

## 本节总结

本节课我们详细拆解了中断的底层处理流程。大家务必要深刻理解：

1.  **硬件排队器**与**中断响应优先级原则**。
2.  **两级指针寻址机制**（排队器信号 $\rightarrow$ 向量地址 $\rightarrow$ 中断向量 $\rightarrow$ 服务程序入口）。
3.  **隐指令与服务程序的分工**：隐指令是由硬件做的“关中断、存断点、找入口”；服务程序是软件做的“存现场、真干活、恢现场、开中断”。
4.  这种在整个中断处理期间始终处于关中断状态的方式称为**单重中断**。下一节我们将探讨更复杂的“多重中断（中断嵌套）”
