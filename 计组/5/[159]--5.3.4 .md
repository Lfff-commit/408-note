> **导语**

## 一、 单总线数据通路的核心特征

在图示的数据通路中，所有内部部件（如 PC、MAR、MDR、ALU、通用寄存器 GPRs 等）都挂载在**唯一的一条内部总线**上。

- **互斥共享的铁律**：由于只有一根总线（就像只有一条单行道），同一时刻只能允许**一个部件发送数据**（上总线），但可以允许一个或多个部件接收数据（下总线）。
- **多周期特性**：如果一条指令需要发生多次数据搬运（比如既要把操作数 A 搬到 ALU，又要搬操作数 B），由于总线的互斥性，这些动作**必须被错开安排在不同的时钟周期内**。因此，基于单总线的数据通路必定是**多周期 CPU**。

### 关键控制信号解读 (控制部件 CU 的“指挥棒”)

控制单元 CU 通过发出两类主要信号来控制数据的流动：

1.  **`X_out` (输出控制/三态门控制)**：控制某部件（如 `PC_out`, `MDR_out`, `GPR_out`）将数据打到内部总线上。物理本质是控制**三态门**导通。
2.  **`Y_in` (输入控制)**：允许总线上的数据写入某部件（如 `MAR_in`, `IR_in`, `GPR_in`）。

## 二、 黄金阶段一：取指阶段 (所有指令完全相同)

无论什么指令，第一步都必须先把它从主存中取进 CPU 的指令寄存器 (IR) 中。这个过程分为三大动作，耗费若干时钟节拍。
假设当前 `PC = 0x9AF0`，我们要取出这条地址处的指令。

| 时钟节拍  | 核心动作说明                                            | 控制单元 (CU) 发出的有效控制信号     | 数据流向与结果                                                                                          |
| :-------: | :------------------------------------------------------ | :----------------------------------- | :------------------------------------------------------------------------------------------------------ |
|  **C1**   | **把 PC 值送入 MAR**，<br> 同时 **PC 自动指向下一条**。 | `PC_out`, `MAR_in`, `PC+1`           | `PC` 值打上总线，落入 `MAR`。 <br> _(注：此例中机器字长=指令长=2B，故实际是 PC+2 $\rightarrow$ 0x9AF2)_ |
| **C2~C6** | **通知主存进行读操作**。<br> 主存较慢，需等待数个周期。 | `Read` (系统总线控制), <br> `MDR_in` | 主存根据 `MAR` 地址查出指令代码，通过系统数据总线送回 `MDR`。                                           |
|  **C7**   | **将指令送入 IR** 供 CU 译码。                          | `MDR_out`, `IR_in`                   | `MDR` 中的指令代码打入内部总线，落入 `IR`。                                                             |

> **🌟 破题心法**：在 408 考研综合题中，只要看到“取指周期”的微操作序列填空，不管后面的指令有多花哨，这三步操作 (`PC->MAR`, `MEM->MDR`, `MDR->IR`) 永远是雷打不动的标准开局！

## 三、 黄金阶段二：执行阶段 (指令各显神通)

CU 解析 IR 中的操作码后，会根据指令的不同，编排截然不同的后续时钟动作。

### 案例 1：执行 `ADD R2, R1` (寄存器相加)

- **功能语义**：将寄存器 `R1` 与 `R2` 的值相加，结果存回 `R2`。(`R2 = R1 + R2`)
- **痛点分析**：ALU 需要同时输入 `R1` 和 `R2`。但在单总线上，同一时刻只能搬一个数据！这就必须用到 ALU 前端的**暂存寄存器 Y**。

| 时钟节拍 | 核心动作说明                                                                                | 有效控制信号                                              |
| :------: | :------------------------------------------------------------------------------------------ | :-------------------------------------------------------- |
|  **C8**  | **送左操作数到 Y**。<br> 不能直接送 ALU，因为总线还要运右操作数。                           | `GPR_out`, `rs(0001)`, `Y_in` <br> _(将 R1 送入暂存器 Y)_ |
|  **C9**  | **送右操作数并执行加法**。<br> R2 直通 ALU 右端，与 Y 寄存器同时运算。结果暂存至 Z 寄存器。 | `GPR_out`, `rd(0010)`, <br> `ALUop(ADD)`                  |
| **C10**  | **结果写回**。<br> 将 Z 寄存器的结果通过总线写回 R2。                                       | `Z_out`, `GPR_in`, `rd(0010)`                             |

### 案例 2：执行 `MOV R2, (R1)` (取数指令)

- **功能语义**：以寄存器 `R1` 中的值作为内存物理地址，去主存中取数据，将数据放入寄存器 `R2` 中。(寄存器间接寻址)

|  时钟节拍  | 核心动作说明                                  | 有效控制信号                                                    |
| :--------: | :-------------------------------------------- | :-------------------------------------------------------------- |
|   **C8**   | **送有效地址到 MAR**。<br> 准备去主存读数据。 | `GPR_out`, `rs(0001)`, `MAR_in` <br> _(将 R1 中的地址送入 MAR)_ |
| **C9~C13** | **通知主存进行读操作**。<br> 漫长的主存等待。 | `Read`, `MDR_in` <br> _(主存查出数据送回 MDR)_                  |
|  **C14**   | **结果写入目的寄存器**。                      | `MDR_out`, `GPR_in`, `rd(0010)` <br> _(将 MDR 中的数据写回 R2)_ |

## 四、 本节核心逻辑沉淀

通过对比 `ADD` 和 `MOV` 的执行流程，我们需要形成以下肌肉记忆：

1.  **万变不离其宗的取指**：只要是一条指令的生命周期，开头的取指动作绝对是标准化的模板拷贝。
2.  **单总线的“交通管制”**：永远不要试图在一个时钟节拍内，让两个源部件同时把 `out` 信号打开！必须借助**暂存器 (Y, Z)** 进行“错峰出行”。
3.  **地址码的特殊定位**：表格中紫色的 `rs`、`rd` 等寄存器编号，**不是 CU 自己生成的，而是 CU 从 `IR` 指令寄存器中的操作码字段拆解出来的**。
4.  **CPU 到底有多灵活？** 同一套错综复杂的硬件线路，仅仅因为 CU 在不同的时钟节拍里弹奏了不同的 `in/out` 控制信号组合，就能变幻出加减乘除、内存读写等千变万化的程序逻辑。这就是冯·诺依曼架构中“存储程序、自动执行”的极致魅力。
