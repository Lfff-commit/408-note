# 计算机组成原理：数据寻址方式 (上)

> **导语**
> 各位同学大家好，在上一小节中，我们学习了“指令寻址”（即 CPU 如何确定下一条要执行的指令地址）。本节课，我们将把目光转向指令内部的地址码——探讨 **“数据寻址”**。
> 为什么一条指令里给出的地址码不能直接被当成真实地址来用？因为在现代计算机中，程序在内存中的存放位置是动态变化的，甚至同一个操作数可能藏在寄存器里、堆栈里，或者干脆直接写在指令里。本节课我们将系统学习前六种常用的数据寻址方式，彻底搞懂 CPU 是如何通过“形式地址”一步步剥丝抽茧，找到最终的“有效地址 (EA)”的。

---

## 一、 数据寻址的核心概念

### 1. 为什么需要数据寻址？

- **程序浮动**：一段程序在编译时，其内部逻辑地址总是从 `0` 开始。但当它被操作系统加载到主存运行时，可能会被存放在主存地址 `100`、`200` 等任意位置。如果直接把指令中的地址码当成物理地址硬套，必然会导致读写错误。
- **灵活性需求**：我们需要通过某种规则（如基址偏移、间接指针、相对 PC 偏移等）来动态解读地址码，从而极大地提高编程的灵活性和主存的利用率。

### 2. 形式地址 (A) 与 有效地址 (EA)

为了明确地址的解读规则，指令的结构被进一步细化为：

```mermaid
graph LR
    subgraph 指令的数据寻址结构
        direction LR
        OP[操作码 OP] --- MODE[寻址特征 <br> (几个比特, 标识寻址方式)] --- ADDR[形式地址 A]
    end
```

- **形式地址 (A, Formal Address)**：指令字中给出的原始地址码字段。它只是一个寻找数据的“线索”。
- **有效地址 (EA, Effective Address)**：经过“寻址特征”规定的运算规则处理后，得到的**最终操作数所在的真实物理地址**。
- **符号约定**：`(A)` 表示地址为 `A` 的主存单元或寄存器中存放的**实际数据内容**。

## 二、 基础数据寻址方式解析

本节课我们将介绍十种常见数据寻址方式中的前六种。在分析时，请重点关注**有效地址的计算公式**以及**指令执行阶段的访存次数**（注意：这不包含取指令本身的那 1 次访存）。

### 1. 隐含寻址 (Implied Addressing)

- **原理**：指令中**根本不显式给出操作数的地址**，而是由操作码默认“潜规则”指明某个操作数藏在特定的硬件中（通常是累加器 `ACC`）。
- _示例_：加法指令只需给出一个加数的地址，另一个加数默认在 `ACC` 里。运算结果也默认存回 `ACC`。
- **有效地址**：程序员不可见，由硬件自动确定。
- **优点**：缩短指令字长。
- **缺点**：需增加专门的硬件存储隐含操作数。

### 2. 立即寻址 (Immediate Addressing)

- **原理**：形式地址 `A` 根本不是一个地址！它直接就是**操作数本身**（又称立即数）。
- _特征_：在汇编语言中，通常用 `#` 号标识（如 `ADD #3`，表示把数字 3 加到寄存器里）。立即数多采用补码表示。
- **有效地址**：无有效地址，**操作数 = A**。
- **执行期访存次数**：**0 次**（数据已经跟着指令一起被取进 CPU 了）。
- **优缺点**：速度最快（无需访存找数据）；但操作数大小受限于指令中 `A` 字段的位数。

### 3. 直接寻址 (Direct Addressing)

- **原理**：最直观的方式。指令中的形式地址 `A` 就是操作数存放的真实物理地址。
- **有效地址公式**：**EA = A**。
- **执行期访存次数**：**1 次**（拿着 A 直接去主存取数）。
- **优缺点**：执行简单，不需要额外的地址计算；但寻址范围被 `A` 的位数死死限制，且程序不易在内存中浮动。

### 4. 间接寻址 (Indirect Addressing)

- **原理**：形式地址 `A` 指向的是一个主存单元，但这个主存单元里装的不是我们要的数据，而是**真实数据存放的地址**（类似于 C 语言的指针）。
- **有效地址公式**：**EA = (A)**。（即把 A 里的内容取出来当地址用）。
- **多次间址**：如果主存单元的第一位标志为 `1`，说明里面装的还是个地址，还得继续往下找（指针的指针），直到标志位为 `0` 才找到最终的 EA。
- **执行期访存次数**：一次间接寻址为 **2 次**（第一次去主存取 EA，第二次拿着 EA 去主存取数据）。
- **优缺点**：极大地扩大了寻址范围，非常方便实现函数的嵌套调用和返回；但访存次数多，**执行速度慢**。

### 5. 寄存器寻址 (Register Addressing)

- **原理**：形式地址给出的是 CPU 内部某个**通用寄存器的编号 ($R_i$)**，操作数就乖乖躺在这个寄存器里。
- **有效地址公式**：**EA = $R_i$**。
- **执行期访存次数**：**0 次**（只访问寄存器，不访问主存）。
- **优缺点**：速度极快，指令字短（因为寄存器数量少，编号只需几个比特）；但寄存器价格昂贵，数量极其有限。

### 6. 寄存器间接寻址 (Register Indirect Addressing)

- **原理**：间接寻址的“优化版”。这次作为指针存放中间地址的不是慢速的主存，而是 CPU 内部的高速寄存器。形式地址给出寄存器编号 $R_i$，**该寄存器中装的才是最终的物理主存地址**。
- **有效地址公式**：**EA = ($R_i$)**。
- **执行期访存次数**：**1 次**（读寄存器不耗时，拿到 EA 后只需去主存取 1 次数据）。
- **优缺点**：比普通的间接寻址少了一次漫长的主存访问，速度更快；同时具备了扩大寻址范围和方便指针操作的优点。

## 三、 本节要点对比总结

请将下表深深印在脑海中，这是期末考试和考研选择题的必考点阵地：

| 寻址方式           | 有效地址 (EA) 计算 | 含义说明                          | 执行期访存次数 | 主要优缺点                            |
| :----------------- | :----------------- | :-------------------------------- | :------------: | :------------------------------------ |
| **隐含寻址**       | 无                 | 操作数隐藏在 ACC 等特殊硬件中     |       0        | 缩短指令字长 / 需特殊硬件             |
| **立即寻址**       | 操数 = A           | A 直接就是操作数（常量）          |     **0**      | 速度最快 / 数值范围极小               |
| **直接寻址**       | EA = A             | A 就是真实物理主存地址            |       1        | 简单 / 寻址范围受限，不可浮动         |
| **间接寻址**       | EA = (A)           | A 是主存中的指针 (存放最终地址)   |  **$\ge$ 2**   | 寻址范围极大，利于函数调用 / **最慢** |
| **寄存器寻址**     | EA = $R_i$         | 数据就在 CPU 寄存器 $R_i$ 中      |     **0**      | 极快，指令短 / 寄存器数量有限         |
| **寄存器间接寻址** | EA = ($R_i$)       | 寄存器 $R_i$ 中存放最终的主存地址 |       1        | 比间接寻址快，利于数组和指针操作      |

_(注：以上“执行期访存次数”均不包含取指令本身的 1 次访存。)_
