# 机器级代码：AT&T 格式与 Intel 格式的对比

> **导语**
> 各位同学大家好，在之前的课程中，我们学习的底层代码都是基于 **Intel 格式** 的 x86 汇编语言（这也是 408 统考真题默认的格式）。
> 但在实际的计算机科学领域，特别是 Unix/Linux 生态和 GCC 编译器中，广泛使用的是另一种由贝尔实验室发明的格式——**AT&T 格式**。为了保证我们在阅读教材、做模拟题或是未来面对命题风格的变化时能游刃有余，本节课我们将对这两种格式进行全面、直观的对比。只要掌握了本文总结的五个核心差异，你就能轻松在这两种格式间无缝切换。

---

## 一、 为什么会有两种格式？

- **Intel 格式**：由 Intel 公司主导制定，广泛应用于 Windows 体系和微软的各类编译器（如 Visual Studio）。**408 考研历年真题通常采用此格式**。
- **AT&T 格式**：由大名鼎鼎的贝尔实验室（Unix、C 语言的诞生地）制定。广泛应用于 Unix、Linux 系统以及 GCC 编译器生态中。

> 💡 **备考策略**：在考研中，如果题目出现汇编代码且没有特别注释，默认按 **Intel 格式** 解读。如果你在题目中看到了 `%` 或 `$` 符号，就要立刻反应过来这是 **AT&T 格式**。

---

## 二、 五大核心差异对比 (★ 终极速查表)

为了方便记忆，我们将两者的所有核心区别浓缩在以下对比中。请重点关注**操作数方向**和**寻址符号**的差异。

### 1. 操作数的方向 (最易混淆的致命点)

这两种格式在数据的流转方向上**完全相反**！

- **Intel 格式 (右到左)**：`指令 目的操作数(d), 源操作数(s)`
  - _记忆法则_：和 C 语言的赋值语句 `d = s` 一样，把右边赋给左边。
  - _示例_：`MOV EAX, EBX` (将 EBX 复制到 EAX)
- **AT&T 格式 (左到右)**：`指令 源操作数(s), 目的操作数(d)`
  - _记忆法则_：像箭头的指向一样顺着来，把左边送到右边。
  - _示例_：`movl %ebx, %eax` (将 EBX 复制到 EAX)

### 2. 寄存器与常量的标识符

AT&T 格式非常强调符号化，必须加上特定的前缀才能被识别为寄存器或立即数。

| 元素             | Intel 格式 | AT&T 格式          | 示例对比                           |
| :--------------- | :--------- | :----------------- | :--------------------------------- |
| **寄存器**       | 直接写名称 | 必须加前缀 **`%`** | Intel: `EAX` <br> AT&T: **`%eax`** |
| **立即数(常量)** | 直接写数值 | 必须加前缀 **`$`** | Intel: `985` <br> AT&T: **`$985`** |

### 3. 主存地址的括号表示

当操作数位于主存时，需要使用括号将地址或指针括起来。

- **Intel 格式**：使用中括号 **`[ ]`**。
  - _示例_：`MOV EAX, [EBX]`
- **AT&T 格式**：使用小括号 **`( )`**。
  - _示例_：`movl (%ebx), %eax`

### 4. 读写长度的指定方式

当访问内存时，如何告诉 CPU 是读 8 位、16 位还是 32 位？

- **Intel 格式 (前缀限定词)**：在 `[ ]` 前面加 `BYTE PTR`, `WORD PTR`, `DWORD PTR`。
  - _示例_：`MOV DWORD PTR [AF996H], EAX` (写 32 位)
- **AT&T 格式 (指令后缀字母)**：直接在操作码助记符后面加上后缀 `b` (byte), `w` (word), `l` (long/dword)。
  - _示例_：`movl %eax, (0xAF996)` (写 32 位)
  - _默认规则_：如果在 AT&T 中省略了后缀，和 Intel 一样，**默认按 32 位处理**。

### 5. 主存寻址表达式写法 (相对偏移与基址变址)

这是最复杂的一种情况。在处理结构体数组时，我们通常需要用到复合寻址：
**最终地址 = 基地址 + 变址 $\times$ 比例因子 + 偏移量**

- **Intel 格式**：像写 C 语言表达式一样，直接全塞进中括号 `[ ]` 里。
  - _语法_：`[ 基址寄存器 + 变址寄存器 * 比例因子 + 偏移量 ]`
  - _示例_：`MOV EAX, [EBX + ECX * 32 + 4]`
- **AT&T 格式**：有严格的占位符格式。偏移量写在小括号外面。
  - _语法_：`偏移量(基址寄存器, 变址寄存器, 比例因子)`
  - _示例_：`movl 4(%ebx, %ecx, 32), %eax` (注意：`4` 放在括号外，括号内用逗号隔开)

## 三、 C 语言底层数据结构寻址的奥秘

为什么汇编语言要设计这么复杂的“基址+变址+比例因子+偏移量”的寻址方式呢？
其实，这是专门为了高效处理高级语言中的**结构体数组 (Struct Array)** 而量身定制的。

**【场景推演】**
假设 C 语言中有一个结构体数组 `struct Student students[100];`，每个结构体占用 **32 字节**。其中，第 **4 个字节** 开始存放的是学生的年龄 (`age`)。
现在我们要用汇编读取 `students[i].age` 的值。

```mermaid
graph TD
    subgraph 结构体数组内存布局
        BASE[数组起始基地址 <br> (存于 基址寄存器 EBX)]
        INDEX[当前学生索引 i <br> (存于 变址寄存器 ECX)]
        SIZE[单学生数据大小 <br> (比例因子: 32字节)]
        OFFSET[age 字段偏移 <br> (偏移量: 4字节)]

        BASE -->|基址| ADDR1((定位数组头))
        INDEX -.->|乘以 32| ADDR2((定位第 i 个学生头))
        OFFSET -.->|加 4| ADDR3((定位该学生的 age))
    end
```

**寻址公式硬解：**

1.  找到数组开头：`基地址 (EBX)`
2.  找到第 `i` 个学生：`i (ECX)` $\times$ `32 (比例因子)`
3.  跳过姓名学号，直接指向年龄：`+ 4 (偏移量)`
4.  组合起来：**真实内存地址 = EBX + ECX $\times$ 32 + 4**。

这完美对应了汇编指令：

- Intel: `[EBX + ECX*32 + 4]`
- AT&T: `4(%ebx, %ecx, 32)`

## 四、 本节知识汇总对译表

将上述规则融会贯通后，请尝试对照阅读以下等价指令表：

| 操作意图                  | Intel 格式 (右向左传, `[]`)   | AT&T 格式 (左向右传, `()`, 带 `%` `$`) |
| :------------------------ | :---------------------------- | :------------------------------------- |
| **寄存器到寄存器**        | `MOV EAX, EBX`                | `movl %ebx, %eax`                      |
| **常数到寄存器**          | `MOV EAX, 985`                | `movl $985, %eax`                      |
| **取指针指向的值**        | `MOV EAX, [EBX]`              | `movl (%ebx), %eax`                    |
| **内存到寄存器 (带偏移)** | `MOV EAX, [EBX - 8]`          | `movl -8(%ebx), %eax`                  |
| **写 8位 到内存**         | `MOV BYTE PTR [EAX], 5`       | `movb $5, (%eax)`                      |
| **结构体数组寻址读取**    | `MOV EAX, [EBX + ECX*32 + 4]` | `movl 4(%ebx, %ecx, 32), %eax`         |

> **一句话总结**：在做题时，看到 `MOV A, B`。如果代码里没有任何 `%` 和 `$` 符号，就把 `B` 赋给 `A`；如果代码里全是 `%` 和 `$` 符号，就把 `A` 赋给 `B`。
