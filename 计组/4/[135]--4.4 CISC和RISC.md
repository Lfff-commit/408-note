# 计算机组成原理：CISC 与 RISC 指令系统对比

> **导语**
> 各位同学大家好，本小节我们将学习指令系统这一章的最后一个重要概念：**CISC 与 RISC**。
> 前面的课程中，我们了解了指令的格式、指令寻址和数据寻址，感受到了指令系统设计的千变万化。CISC 和 RISC 则是两种截然不同的指令系统设计理念。通过本节课的简要对比，我们将为第五章关于微程序和流水线的学习打下基础。

## 一、 核心设计思想对比

### 1. CISC (Complex Instruction Set Computer)

- **概念**：**复杂指令集计算机**。
- **设计思想**：指令系统中包含大量复杂的指令，一条指令就能完成一个非常复杂的基本功能。
- **代表架构**：**x86 架构**（广泛应用于笔记本、台式机、商业服务器等对功能复杂性要求高的场景）。
- **通俗类比**：就像为你提供了一门带有海量现成“库函数”的编程语言，想干什么复杂的事直接调库就行。
- **发展瓶颈 (80-20 定律)**：人们发现，典型程序中 **80% 的语句仅仅使用了 20% 的最基本指令**，而剩下 80% 的复杂指令极少被用到，却极大地增加了硬件电路设计的复杂度和成本。

### 2. RISC (Reduced Instruction Set Computer)

- **概念**：**精简指令集计算机**。
- **设计思想**：只提供最核心、最基本、最常用的指令。复杂的功能由多条简单指令组合完成。
- **代表架构**：**ARM 架构**（广泛应用于智能手机、平板电脑等移动设备）。
- **通俗类比**：只提供 C 语言最基本的 `if-else`、`for` 循环和基础加减乘除，不提供复杂的库函数。你想做复杂的事，就用基础语法自己手写。
- **优势**：硬件电路设计简单，功耗极低（适合移动设备）；指令执行时间短且规整，极度契合流水线技术。

## 二、 硬件实现方式的差异探讨

为了更直观地理解，我们来看一个**“矩阵运算”**的场景假设：系统需要支持整数加减乘，以及复杂的矩阵加减乘。

### CISC 的困境与“微程序”

- 如果按 CISC 的思路，必须设计出 6 种专门的硬件电路，分别对应这 6 种操作。但“矩阵乘法”的硬件电路设计起来极其困难。
- **解决方案 (微程序)**：为了实现这种超复杂指令，CISC 引入了**微程序**的设计思想。即在 CPU 内部，将一条复杂的“矩阵乘法”指令拆解为多条底层的基础简单操作序列（存放在控制存储器中）。对外看似是一条指令，对内其实执行了一段“微型代码”。

### RISC 的化繁为简

- 按 RISC 的思路，硬件层面**只提供整数加减乘的电路**。
- 当程序员或编译器需要做矩阵乘法时，只能通过编写一段包含循环和基础乘法指令的程序来组合实现。
- **结果**：每条 RISC 指令的硬件实现都极其简单直接。

## 三、 CISC 与 RISC 核心特性终极对比表

以下对比表是考研选择题的常客，请务必熟练掌握各项差异背后的逻辑原因。

| 对比维度       | CISC (复杂指令集)                   | RISC (精简指令集)                                   | 核心逻辑推演                                                      |
| :------------- | :---------------------------------- | :-------------------------------------------------- | :---------------------------------------------------------------- |
| **指令系统**   | 复杂庞大，指令条数多 (一般 >200)    | 简单精简，指令条数少 (一般 <100)                    | RISC 砍掉了不常用的复杂指令。                                     |
| **指令字长**   | **不固定** (变长指令字)             | **固定** (定长指令字)                               | RISC 指令功能单一，容易做成定长，解码极快。                       |
| **执行时间**   | 各种指令执行时间相差很大            | 绝大多数指令**在一个时钟周期内完成**                | RISC 去掉了需要超长周期的复杂指令。                               |
| **访存指令**   | 不加限制 (如乘法指令可直接读取内存) | **严格限制，只有 `LOAD` 和 `STORE` 指令能访问主存** | 如果运算指令能直接访存，执行时间就无法保证一个周期，破坏流水线。  |
| **通用寄存器** | 较少                                | **非常多**                                          | RISC 运算前必须先用 `LOAD` 把数据取到寄存器，长线运算极耗寄存器。 |
| **编译优化**   | 难以用优化编译生成高效代码          | **高度依赖优化编译程序**生成高效代码                | RISC 像搭积木，编译器可以通过巧妙排布简单指令来榨干性能。         |
| **控制方式**   | 绝大多数采用**微程序控制**          | 绝大多数采用**组合逻辑控制** (硬布线控制)           | 微程序慢但能处理复杂；组合逻辑快但只能处理简单逻辑。(第五章重点)  |
| **指令流水线** | 可以实现，但较困难                  | **必须实现**，且极易实现                            | RISC 指令规整、单周期执行，天生为流水线而生。(第五章重点)         |
