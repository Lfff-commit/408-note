# 路由聚合与最长前缀匹配

## 一、路由聚合的背景

本节学习**路由聚合（Route Aggregation）**，它与 **CIDR 无分类编址**配套使用。

假设“咸鱼电信”获得了一个 CIDR 地址块，并将其划分为四个子网：

- 子网 1：分配给铁柱的网吧。
- 子网 2：分配给旺财家。
- 子网 3：分配给狗剩家。
- 子网 4：暂时没有分配使用。

咸鱼电信的路由器通过不同接口连接三个已使用的子网：

| 接口 | 连接对象         |
| ---- | ---------------- |
| F1   | 铁柱的网吧       |
| F2   | 旺财家           |
| F3   | 狗剩家           |
| F0   | 县里的电信路由器 |

县里的电信路由器通过 G1 接口将发往这三个子网的数据报转发给咸鱼电信路由器。县里的路由表中，分别存在指向铁柱网吧、旺财家和狗剩家三个子网的路由表项。

## 二、路由聚合的概念

### 1. 聚合的条件与方法

将三个子网对应的网络前缀展开为二进制后，可以发现：

- 三个网络前缀的**前 27 位完全相同**。
- 三条路由表项的**转发接口相同**，都指向 G1。

因此，可以把三条路由表项聚合为一条路由表项，只保留共同的前 27 位。聚合后的表项仍然从 G1 接口转发。

```text
表项 1 ─┐
表项 2 ─┼──> 聚合为表项 4：共同的前 27 位，转发接口 G1
表项 3 ─┘
```

聚合后的表项表示：当县里的电信路由器收到一个 IP 数据报时，如果其目的 IP 地址的前 27 位与表项 4 的前 27 位一致，就可以从 G1 接口转发。

例如，发往铁柱网吧子网的 IP 数据报，其目的地址仍然能够匹配聚合后的前 27 位，因此仍会从 G1 接口转发。路由聚合不会影响这些原有目的地址的正常转发。

### 2. 定义

如果路由器转发表中的多条路由表项满足以下条件：

1. **转发接口相同**；
2. **网络前缀存在共同部分**；

就可以将这些路由表项聚合为一条路由表项，只保留共同的网络前缀，并保持原有的转发接口。

这一过程称为**路由聚合**，也称为**构成超网**。

## 三、路由聚合的优点

### 1. 减小路由表规模

多条路由表项合并为一条后，路由转发表占用的内存更少。

### 2. 提高查表效率

路由表项减少后，路由器查询转发表时需要检查的表项可能减少，从而提高查表效率、降低转发时延。

## 四、路由聚合的限制与影响

### 1. 转发接口不同，不能直接聚合

路由聚合要求被聚合的路由表项具有相同的转发接口。

例如，咸鱼电信路由器的表项分别指向 F1、F2、F3。虽然这些表项的网络前缀可能存在共同部分，但它们的转发接口不同，因此不能合并为一条路由表项。

原因是：合并后只保留一个转发接口，就无法正确地将数据报分别转发到不同的子网。

### 2. 聚合可能覆盖额外的无效地址

咸鱼电信获得的地址块被划分为四个子网，但只有三个子网正在使用，第四个子网暂时没有分配。

路由聚合时，只保留三个已使用子网共同的前 27 位，因此聚合后的地址范围也可能包含第四个暂未使用的子网地址。

如果某个 IP 数据报的目的地址属于这个暂未使用的子网，它也可能匹配县里电信路由器的聚合表项，并被转发到 G1。

到达咸鱼电信路由器后，该路由器检查自己的路由表，发现没有任何具体路由表项匹配该目的地址，只能匹配默认路由。由于数据报进入的接口与默认路由所指向的出口相同，路由器不应将数据报再转发回原方向，因此可以将其丢弃。

**结论：**路由聚合可能引入额外的无效地址，但通常不会影响网络的正常工作。

### 3. 路由聚合与最长前缀匹配

路由聚合后，一个目的 IP 地址可能同时匹配多条路由表项。在这种情况下，需要使用**最长前缀匹配原则**选择路由。

最长前缀匹配的核心是：

> 当一个目的 IP 地址同时匹配多条路由表项时，选择网络前缀最长、也就是匹配位数最多的那一条。

## 五、最长前缀匹配示例

### 示例一：铁柱网吧额外连接县里电信路由器

假设铁柱网吧认为通过咸鱼电信转发的性能不够理想，于是额外拉一条线路，直接连接县里的电信路由器。

县里电信路由器的 G3 接口直接连接铁柱网吧所在的子网，因此 G3 接口的 IP 地址必须从该子网对应的地址块中选择。示例中给 G3 分配地址 `192.168.1.130`（此处仅用于说明接口地址的分配方式；实际地址应以题目给定的地址规划为准）。

县里电信路由器新增一条指向铁柱网吧子网的路由表项，网络前缀为 28 位，转发接口为 G3。

假设有一个 IP 数据报的目的地址是 `192.168.1.131`。它可能同时匹配：

- 聚合路由：前 27 位匹配，转发接口为 G1；
- 铁柱网吧的具体路由：前 28 位匹配，转发接口为 G3；
- 默认路由：前 0 位匹配。

其中，具体路由的前缀长度为 28 位，比聚合路由的 27 位和默认路由的 0 位都长。因此，应选择具体路由，从 G3 接口转发，直接到达铁柱网吧子网。

```text
目的地址：192.168.1.131

匹配的路由：
  聚合路由：前缀长度 /27  ──> G1
  具体路由：前缀长度 /28  ──> G3
  默认路由：前缀长度 /0   ──> 默认出口

最长前缀匹配：/28
最终从 G3 接口转发
```

### 示例二：目的地址为狗剩主机

假设 IP 数据报的目的地址是狗剩主机的地址 `192.168.1.153`。

检查县里电信路由器的路由表：

- 目的地址的前 27 位可以匹配聚合路由；
- 目的地址的前 28 位不能匹配铁柱网吧的具体路由；
- 默认路由始终可以匹配。

因此，按照最长前缀匹配原则，应选择前缀长度为 27 位的聚合路由，从 G1 接口转发。数据报到达咸鱼电信路由器后，再由其具体路由表项从 F3 接口转发，最终到达狗剩主机。

## 六、CIDR、子网划分与路由聚合综合理解

前面课程中的网络可以综合理解为以下几种情况：

| 网络           | 地址规划方式                       | 特点                                             |
| -------------- | ---------------------------------- | ------------------------------------------------ |
| 学校网络       | 申请网络前缀为 16 位的 CIDR 地址块 | 采用定长子网划分，分为两个大小相等的子网         |
| 公司网络       | 申请网络前缀为 24 位的 CIDR 地址块 | 内部没有继续划分子网                             |
| 咸鱼电信网络   | 对地址块进行变长子网划分           | 划分为三个正在使用的子网，另有一个子网暂未使用   |
| 县里电信路由器 | 使用路由聚合                       | 将多个具有共同前缀、且转发接口相同的路由表项聚合 |

铁柱网吧的子网可以同时连接两台路由器，这种连接方式是允许的。但铁柱网吧内的每台主机除了配置 IP 地址和子网掩码，还需要配置默认网关。

默认网关用于指定：当主机要发送的数据报目的地址不在本地子网时，应将数据报交给哪一个路由器接口。

对铁柱网吧而言，可以将默认网关配置为县里电信路由器的 G3 接口地址 `192.168.1.130`，这样数据报可以直接进入县里电信路由器。也可以配置为咸鱼电信路由器在该子网中的接口地址，但数据报会多经过一次路由转发。

## 七、主机发送 IP 数据报的过程

主机发送 IP 数据报时，主要涉及以下步骤：

1. 网络层构造 IP 数据报，填写源 IP 地址和目的 IP 地址。
2. 判断目的 IP 地址是否与本机处于同一子网。
3. 如果目的地址属于其他网络，则将数据报交给默认网关。
4. 使用 ARP 协议查询下一跳接口的 MAC 地址。
5. 将 IP 数据报封装成数据链路层帧，填写目的 MAC 地址。
6. 交换机根据目的 MAC 地址转发帧。
7. 路由器收到帧后，取出 IP 数据报，根据目的 IP 地址查询转发表。
8. 路由器选择转发接口，并重新封装数据链路层帧后继续转发。
9. 数据报经过沿途路由器转发，最终到达目的主机。

### 重要说明：IP 地址不带 CIDR 后缀写入数据报

例如，主机的网络前缀长度为 `/28`，另一台主机的网络前缀长度为 `/17`。构造 IP 数据报时，源地址和目的地址只填写各自的 **32 位 IP 地址**，不需要在 IP 首部中附加 `/28` 或 `/17`。

`/28`、`/17` 表示的是网络前缀长度，也就是主机配置的子网掩码中连续 1 的位数，并不是 IP 数据报源地址或目的地址的一部分。

## 八、综合画图训练一：H1 发送给狗剩

假设 H1 要向狗剩主机发送一个 IP 数据报。

### 1. 构造 IP 数据报

- 源 IP 地址：H1 的 IP 地址。
- 目的 IP 地址：狗剩主机的 IP 地址。

IP 数据报的源地址和目的地址在整个转发过程中保持不变（不考虑 NAT 等会改写地址的机制）。

### 2. H1 判断目的地址是否在本地网络

H1 的网络前缀长度为 `/17`，即子网掩码的前 17 位为 1。H1 将本机 IP 地址和目的 IP 地址分别与子网掩码进行逐位与运算，再比较结果：

- 如果结果相同，目的主机在本地子网；
- 如果结果不同，目的主机不在本地子网，应将数据报交给默认网关。

该例中，目的地址不属于 H1 所在子网，因此 H1 将数据报交给默认网关。

### 3. H1 封装帧并交给学校路由器

H1 通过 ARP 查询默认网关接口 B3 的 MAC 地址，将其填写为帧的目的 MAC 地址。交换机根据目的 MAC 地址，将帧转发到 B3 接口。

### 4. 学校路由器查表

学校路由器用目的 IP 地址查询转发表。此时只有默认路由匹配，因此数据报从 B1 接口转发出去。

### 5. ISP 路由器转发

数据报到达 ISP 路由器后，路由器同样根据目的 IP 地址查询转发表。该例中只有默认路由匹配，因此从 A1 接口继续转发。

互联网中间还会经过其他路由器。每台路由器都会根据目的 IP 地址查询自己的转发表，选择下一跳和转发接口。

### 6. 县里电信路由器查表

数据报到达县里电信路由器后：

- 目的地址的前 27 位匹配聚合路由；
- 前 28 位不匹配铁柱网吧的具体路由。

因此选择前缀长度为 27 位的聚合路由，从 G1 接口转发到咸鱼电信路由器。

### 7. 咸鱼电信路由器转发

咸鱼电信路由器查表后，目的地址匹配狗剩所在子网的具体路由，因此从 F3 接口转发。数据报最终到达狗剩主机。

```text
H1
 │ 默认网关
 ▼
学校路由器（默认路由）
 │
 ▼
ISP 路由器（默认路由）
 │
 ▼
互联网中的其他路由器
 │
 ▼
县里电信路由器（匹配 /27 聚合路由）
 │ G1
 ▼
咸鱼电信路由器（匹配狗剩子网路由）
 │ F3
 ▼
狗剩主机
```

## 九、综合画图训练二：铁柱主机发送给 H1

假设铁柱网吧中的主机要向 H1 发送一个 IP 数据报。

### 1. 构造 IP 数据报

- 源 IP 地址：铁柱主机的 IP 地址。
- 目的 IP 地址：H1 的 IP 地址。

注意：IP 数据报中不需要填写 `/28` 或 `/17`，只填写 32 位源、目的 IP 地址。

### 2. 铁柱主机判断目的地址

铁柱主机的网络前缀长度为 `/28`。它将本机 IP 地址和目的 IP 地址分别与子网掩码逐位与，再比较结果。

由于 H1 不在铁柱主机的本地子网中，铁柱主机需要将数据报交给默认网关。

如果铁柱主机的默认网关配置为县里电信路由器 G3 接口，则它通过 ARP 查询 G3 的 MAC 地址，并将帧发送给 G3。

### 3. 县里电信路由器查表

县里电信路由器检查目的 IP 地址：

- 不匹配指向咸鱼电信的相关具体路由；
- 匹配默认路由。

因此，数据报从 G0 接口转发到互联网。

### 4. ISP 路由器查表

数据报到达 ISP 路由器后，目的地址匹配前缀长度为 16 位的学校网络路由，因此从 A2 接口转发到学校路由器。

### 5. 学校路由器查表

学校路由器发现目的地址匹配学校网络中的相应路由表项，因此从 B3 接口转发到 H1 所在子网。

数据报经过交换机转发后，最终到达 H1。

```text
铁柱主机
 │ 默认网关：县里电信 G3
 ▼
县里电信路由器（默认路由）
 │ G0
 ▼
互联网中的路由器
 │
 ▼
ISP 路由器（匹配学校网络 /16）
 │ A2
 ▼
学校路由器（匹配 H1 所在子网）
 │ B3
 ▼
交换机
 │
 ▼
H1
```

## 十、综合画图训练三：H1 发送给铁柱主机

请自行训练 H1 向铁柱主机发送 IP 数据报的过程。与前面的过程类似，只需将源地址和目的地址对调，并逐台检查路由器的转发表。

需要特别注意：当数据报到达县里电信路由器时，可能同时匹配：

- 指向多个子网的聚合路由；
- 指向铁柱网吧的具体路由；
- 默认路由。

此时必须使用**最长前缀匹配原则**。由于铁柱网吧具体路由的网络前缀更长，因此县里电信路由器会优先选择 G3 接口，直接将数据报转发给铁柱网吧。

## 十一、考点总结

### 1. 路由聚合

- 路由聚合与 CIDR 无分类编址配套使用。
- 将多条具有共同网络前缀、且转发接口相同的路由表项聚合为一条。
- 路由聚合也称为**构成超网**。
- 主要优点是减小路由表规模、减少查表工作量。
- 转发接口不同的路由表项不能直接聚合。
- 聚合可能覆盖额外的无效地址，但通常不会影响网络正常工作。

### 2. 最长前缀匹配

- 一个目的 IP 地址可能同时匹配多条路由表项。
- 此时选择网络前缀最长、匹配位数最多的表项。
- `/28` 比 `/27` 更具体，`/27` 比 `/16` 更具体，`/16` 比 `/0`（默认路由）更具体。
- 路由器转发 IP 数据报时，依据目的 IP 地址查表，并按照最长前缀匹配原则选择转发路由。

### 3. 主机发送 IP 数据报

- IP 数据报首部填写 32 位源 IP 地址和目的 IP 地址，不填写 CIDR 后缀。
- 主机通过子网掩码判断目的地址是否属于本地子网。
- 目的地址不在本地子网时，将数据报交给默认网关。
- ARP 用于查询同一链路上下一跳 IP 地址对应的 MAC 地址。
- 路由器每次转发时都根据目的 IP 地址查询自己的转发表，并重新封装链路层帧。
