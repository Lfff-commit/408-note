# 操作系统：信号量机制

> **导语**
> 本节课我们将学习操作系统中极其重要的一个知识点：**信号量机制**。
> 前面我们学习的进程互斥软硬件实现方法都存在“盲等”（违背让权等待）的缺陷，且“检查”与“上锁”往往难以一气呵成。1965 年，荷兰学者 Dijkstra 提出了**信号量机制**，完美解决了这两个痛点。我们将重点掌握**整型信号量**与**记录型信号量**的概念及底层逻辑。

---

## 一、 为什么需要信号量机制？（引言）

回顾我们之前学过的互斥方案，它们存在两个致命问题：

1.  **无法一气呵成**：如双标志先检查法，“检查”和“上锁”操作可能被打断，导致两个进程同时进入临界区。
2.  **违背“让权等待”**：几乎所有前述方案（除部分软件方案的死锁外），当进程进不去临界区时，都会在 CPU 上死循环（盲等），浪费计算资源。

**信号量机制的提出，正是为了：**

- 利用操作系统提供的**原语**（不可中断）来保证操作一气呵成。
- 利用**记录型数据结构**来实现真正的“阻塞”与“唤醒”，实现**让权等待**。

---

## 二、 信号量机制的基本概念

- **信号量 (Semaphore)**：简单理解，它就是一个变量。它可以是简单的整数，也可以是复杂的记录型数据结构。
  - **核心物理意义**：信号量的值用来表示系统中**某种资源的数量**（如：打印机数量）。
- **P/V 操作原语**：用户只能通过操作系统提供的一对**原语**来对信号量进行操作，从而实现互斥与同步。
  - `wait(S)`：也称为 **P 操作**（来自荷兰语 _proberen_，测试）。用于**申请资源**。
  - `signal(S)`：也称为 **V 操作**（来自荷兰语 _verhogen_，增加）。用于**释放资源**。
  - _注：原语在执行过程中不可被中断，一气呵成。_

---

## 三、 整型信号量

整型信号量用一个**单纯的整数**来表示资源的数量。除了初始化，对其只能进行 P 操作和 V 操作。

### 1. 代码逻辑

假设系统中有一台打印机，定义整型信号量 `S = 1`。

```c
int S = 1; // S 表示当前系统中可用的打印机数量

// P 操作 (申请资源)
void wait(int S) {
    while (S <= 0);  // 如果资源数 <= 0，说明被别人占用了，一直死循环盲等！
    S = S - 1;       // 如果 S > 0，跳出循环，把资源数减 1，表示自己占用了该资源
}

// V 操作 (释放资源)
void signal(int S) {
    S = S + 1;       // 使用完资源后，将资源数加 1，归还系统
}
```

### 2. 特点与缺陷分析

- **优点**：`wait` 和 `signal` 是原语，因此“检查（`while`）”和“上锁（`S=S-1`）”是一气呵成的，避免了并发导致的冲突。
- **致命缺陷 (常考点)**：如果 `S <= 0`，进程会被卡在 `while` 循环里疯狂空转。因此，**整型信号量依然存在“盲等”现象，不满足“让权等待”原则！**

---

## 四、 记录型信号量 (极其重要的核心考点)

为了彻底解决“盲等”问题，引入了**记录型信号量**。它不仅记录资源数量，还自带了一个**等待队列 (阻塞队列)**。

### 1. 数据结构定义

```c
typedef struct {
    int value;          // 剩余可用资源的数量
    struct process *L;  // 等待该资源的进程队列 (阻塞队列)
} semaphore;
```

### 2. P/V 操作底层逻辑 (必须深刻理解)

#### P 操作 (申请资源：wait)

```c
void wait(semaphore S) {
    S.value--;                  // 先减 1，表示当前进程申请走了一个资源
    if (S.value < 0) {          // 减完后如果 < 0，说明本来就没有资源了 (或者早就透支了)
        block(S.L);             // 调用 block 原语，将自己阻塞！并排入 S.L 等待队列
    }
}
```

- **重点剖析**：如果 `S.value < 0`，代表此时系统中**没有空闲资源**，且 `S.value` 的绝对值就等于**当前等待队列中被阻塞的进程数量**。由于调用了 `block` 原语，进程主动放弃 CPU 进入阻塞态，**完美实现了“让权等待”！**

#### V 操作 (释放资源：signal)

```c
void signal(semaphore S) {
    S.value++;                  // 先加 1，表示当前进程归还了一个资源
    if (S.value <= 0) {         // 加完后如果 <= 0，说明在自己归还前，S.value 是负数，意味着肯定有人在排队等这个资源！
        wakeup(S.L);            // 调用 wakeup 原语，从等待队列 S.L 的队头唤醒一个进程，把资源交给它
    }
}
```

### 3. 动画演示逻辑提炼 (以 2 台打印机为例)

设初始 `S.value = 2`。

1.  `P0` 执行 P 操作：`value--` 变为 `1`。拿到 1 台，顺利运行。
2.  `P1` 执行 P 操作：`value--` 变为 `0`。拿到 1 台，资源恰好分完。顺利运行。
3.  `P2` 执行 P 操作：`value--` 变为 `-1`。`< 0`，资源不足。`P2` 调用 `block` 进入阻塞队列。
4.  `P3` 执行 P 操作：`value--` 变为 `-2`。`< 0`，资源不足。`P3` 调用 `block` 进入阻塞队列排在 `P2` 后面。
    _(此时 `value = -2`，完美印证了绝对值等于排队人数 2 人)_
5.  `P0` 执行 V 操作释放：`value++` 变为 `-1`。由于 `<= 0`，说明有人排队。系统自动 `wakeup` 唤醒 `P2`，将刚才释放的这台打印机交给 `P2`，`P2` 转为就绪态。
6.  `P1` 执行 V 操作释放：`value++` 变为 `0`。由于 `<= 0`，说明还有人排队。系统 `wakeup` 唤醒 `P3`。
7.  `P2` 用完释放：`value++` 变为 `1`。`> 0`，说明没人排队了，直接走人。

## 五、 本节总结与考点提示

1.  **盲等问题辨析**：
    - **整型信号量**：由于内部是用 `while` 循环实现的，**存在盲等，不满足让权等待**。
    - **记录型信号量**：由于内部使用了 `block` 和 `wakeup` 原语，**不存在盲等，完美实现了让权等待**。
2.  **默认约定**：
    在考研题目中，如果题干只说“对信号量 S 进行 P/V 操作”，而没有特殊说明，**一律默认是指“记录型信号量”**。
3.  **后续预告**：
    本节我们重点理解了 P/V 操作内部到底在干嘛。下一节，我们将利用这对强大的武器，去真正实现**进程互斥**与**进程同步**。一定要能默写出记录型信号量 P/V 操作的内部 C 语言代码逻辑！
