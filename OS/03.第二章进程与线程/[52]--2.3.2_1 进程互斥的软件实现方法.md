# 操作系统：进程互斥的软件实现方法

> **导语**
> 本节课是非常高频的考点，经常在选择题甚至大题中出现。我们将学习**四种进程互斥的软件实现方法**：单标志法、双标志先检查法、双标志后检查法和皮特森（Peterson）算法。
> 学习时，不仅要看懂代码，更要理解每段代码背后“**谦让**”与“**表达意愿**”的生活逻辑。同时，要结合上节课学过的“四大原则”（空闲让进、忙则等待、有限等待、让权等待）来分析每种算法的缺陷。

## 一、 为什么需要进程互斥？（引言）

如果没有进程互斥，并发执行会带来什么问题？
假设系统中有进程 A 和进程 B：

1. 进程 A 正在使用打印机，但用到一半时时间片耗尽，被剥夺处理机。
2. 操作系统调度进程 B 运行，进程 B 也开始使用打印机。
   **结果**：A 和 B 的打印内容混杂在一起，输出混乱。
   **结论**：对临界资源（如打印机），必须实现**互斥访问**，即 A 用完释放后，B 才能开始用。

## 二、 算法一：单标志法 (Turn 变量)

### 1. 算法思想与代码解析

- **核心思想**：用一个变量 `turn` 来表示当前允许哪个进程进入临界区。每次访问完临界区后，把使用权“**谦让**”给另一个进程。
- **生活类比**：老渣和小渣轮流使用一个唯一的马桶。小渣用完必须让给老渣，老渣用完必须让给小渣，严格交替。

```c
int turn = 0; // turn = 0 允许 p0 进入，turn = 1 允许 p1 进入

// P0 进程
while (turn != 0);   // ① 进入区：如果不是轮到自己，就死等 (轮询检查)
critical_section();  // ② 临界区：访问资源
turn = 1;            // ③ 退出区：用完后，把 turn 设为 1，谦让给 p1
remainder_section(); // ④ 剩余区

// P1 进程
while (turn != 1);   // ① 进入区：如果不是轮到自己，就死等
critical_section();  // ② 临界区
turn = 0;            // ③ 退出区：用完后，谦让给 p0
remainder_section(); // ④ 剩余区
```

### 2. 缺陷分析

如果 P0 用完临界区并把 `turn` 改为 1，此时本该 P1 使用。但如果 P1 一直不需要使用临界区（或者 P1 还没运行到这里），那么 `turn` 会一直等于 1。
此时，哪怕临界区是完全空闲的，P0 想再次进入也进不去，因为它被卡在了 `turn != 0`。
**缺陷：违背了“空闲让进”原则**。进程只能严格交替访问，容易造成资源闲置。

## 三、 算法二：双标志先检查法

### 1. 算法思想与代码解析

- **核心思想**：设置一个布尔数组 `flag[]`，用来标记各个进程“**是否想要进入临界区**”（表达意愿）。
  在进入临界区之前，先检查对方是否想进；如果对方不想进，自己再上锁并进入。

```c
bool flag[2] = {false, false}; // 初始化表示都不想进

// Pi 进程 (i=0, j=1)
while (flag[j]);    // ① 检查：对方想进吗？如果想进，我就等
flag[i] = true;     // ② 上锁：对方不想进，我就把自己的标志设为 true，表示我要进
critical_section(); // ③ 临界区
flag[i] = false;    // ④ 退出区：解锁，表示我不想进了
```

### 2. 缺陷分析 (并发导致的问题)

假如 P0 和 P1 并发执行：

1. P0 执行 ① `while(flag[1])`，发现 P1 是 false，跳出循环。**就在此时，发生进程切换！**
2. P1 执行 ① `while(flag[0])`，发现 P0 也是 false，跳出循环。
3. P1 执行 ② `flag[1] = true` 并进入临界区。
4. 切回 P0，P0 接着执行 ② `flag[0] = true`，也进入了临界区！
   **缺陷：违背了“忙则等待”原则**。原因在于“检查”和“上锁”这两个操作**不能一气呵成（不是原子操作）**，中间被打断会导致同时进入临界区。

## 四、 算法三：双标志后检查法

### 1. 算法思想与代码解析

- **核心思想**：为了解决“先检查后上锁”被打断的问题，改为“**先上锁（表达意愿），再检查**”。

```c
bool flag[2] = {false, false};

// Pi 进程 (i=0, j=1)
flag[i] = true;     // ① 上锁：先表达意愿，说我想用
while (flag[j]);    // ② 检查：看看对方是不是也想用？如果对方也想，我就死等
critical_section(); // ③ 临界区
flag[i] = false;    // ④ 退出区：解锁
```

### 2. 缺陷分析 (并发导致死锁)

假如 P0 和 P1 并发执行：

1. P0 执行 ① `flag[0] = true`，说我想用。**发生切换！**
2. P1 执行 ① `flag[1] = true`，说我也想用。
3. 切回 P0，执行 ② `while(flag[1])`，发现对方想用，P0 只能死等。
4. 切回 P1，执行 ② `while(flag[0])`，发现对方也想用，P1 只能死等。
   **缺陷：违背了“空闲让进”和“有限等待”原则**。双方互相僵持，导致**饥饿**，谁都进不去临界区。

## 五、 算法四：皮特森算法 (Peterson's Algorithm)

### 1. 算法思想与生活类比

Peterson 算法完美结合了双标志法（表达意愿）和单标志法（谦让）。
**生活类比（抢马桶/发压岁钱）**：

1. **主动争取**：自己先说“我想用” (`flag[i] = true`)。
2. **主动谦让**：接着跟一句客气话“你先用吧” (`turn = j`)。
3. **检查等待**：如果对方也想用 (`flag[j] == true`)，**并且**自己是最后说客气话的那个人 (`turn == j`)，那自己就老老实实等着。
   谁最后说了客气话，谁就失去了优先行动权。

### 2. 代码解析

```c
bool flag[2] = {false, false}; // 表达意愿
int turn = 0;                  // 表达谦让

// P0 进程 (对方是 P1)
flag[0] = true;                 // 1. 主动争取：我 P0 想要进
turn = 1;                       // 2. 主动谦让：客气一下，把优先权让给 P1
while (flag[1] && turn == 1);   // 3. 检查：如果 P1 也想进，且最后是我让的客气话，我就等
critical_section();             // 4. 临界区：对方不想进，或者对方后说了客气话，我就进
flag[0] = false;                // 5. 退出区：用完了，表示不想进了

// P1 进程的逻辑与 P0 完全对称
```

### 3. 并发推演与优缺点分析

无论进程如何并发切换，由于 `turn` 变量是覆盖写入的，必定只有一个进程是“最后修改 `turn` 的人”，从而打破僵局。

- **优点**：用软件方法完美解决了互斥问题，成功实现了**空闲让进、忙则等待、有限等待**。
- **缺陷：违背了“让权等待”原则**。
  当进程进不去临界区时，会被卡在 `while` 循环里，**一直在 CPU 上空转（忙等待）**，浪费了 CPU 资源，未能及时释放处理机。

## 六、 本节知识脉络速记表

| 软件实现方法          | 核心机制 (变量)             | 违背的互斥原则              | 致命缺陷说明                                            |
| :-------------------- | :-------------------------- | :-------------------------- | :------------------------------------------------------ |
| **单标志法**          | `turn` (轮流谦让)           | 违背 **空闲让进**           | 严格交替，一方不用另一方就永远进不去。                  |
| **双标志先检查**      | `flag` (先查后锁)           | 违背 **忙则等待**           | “查”和“锁”不能一气呵成，可能同时进入。                  |
| **双标志后检查**      | `flag` (先锁后查)           | 违背 **空闲让进、有限等待** | 互相上锁互相僵持，产生饥饿。                            |
| **皮特森 (Peterson)** | `flag` + `turn` (争取+谦让) | 违背 **让权等待**           | 解决了前三个问题，但在进不去时会死循环忙等待，占用CPU。 |

> **思考提示**：双标志先检查法的出发点很好，失败仅因为“检查和上锁”在软件层面可能被打断。如果我们能用**硬件指令**保证这两个动作“一气呵成”，问题就迎刃而解了！这就是下一节要学的**硬件实现方法**。
